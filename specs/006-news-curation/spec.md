# Feature Specification: 每日晨報單次 LLM 策展與降級備援（News Curation & Graceful Fallback）

**Feature Branch**: `006-news-curation`

**Created**: 2026-07-18

**Status**: Draft

**Input**: User description: "006-news-curation"

> 範圍依真實來源界定：`docs/tech-radar-dev-guide.md` §4.4 階段 B、§10，以及 §11.2 的 F6 條目；
> 憲章原則 III（新聞每日精選 6 則、配額 AI ≥4 / 其他合計 ≤2、標題 ≤50 / 內容 ≤300、繁中、依開發者
> 重要性排序）、V（每日僅呼叫 Gemini 一次、禁用 embeddings / 向量檢索）、VI（LLM 不得產生事實數據、
> 防幻覺）、VII（來源隔離容錯、失敗不無聲）、VIII（新聞配額與字數上限、策展失敗降級備援須有測試）。
>
> F6 交付**新聞資料流的後半段（階段 B）＋榜單日封面摘要**，共三塊：**(1) 每日單次 Gemini 策展**
> ——把 F4 收斂出的候選集一次交給 LLM，在同一次呼叫內完成「殘留語意去重 → 依開發者重要性挑 ≤6 則
> → 配額約束 → 每則精煉為繁中標題 ≤50 字＋內容 ≤300 字」，並以程式硬驗證字數與配額、不足不硬湊；
> **(2) 策展失敗的降級備援**——LLM 呼叫失敗時退回「純程式排序（沿用 F4 漏斗 `weightedScore`）取前 6」，
> 每則僅呈現原文標題＋連結（無繁中改寫），不阻斷晨報；**(3) 榜單日「本次變化」TL;DR**——把榜單 diff
> 摘成一句繁中封面文案（另一次 LLM 呼叫，重用 F5 的 `LlmService`），失敗時退回程式產生的事實型摘要。
>
> **本 Feature 不含**：新聞來源抓取、正規化、階段 A 零 LLM 去重與過濾（F4 `004-news-ingest`，已驗收
> ——F6 消費其 `CandidateSet` 產物）；repo 250 字簡介與 `LlmService` 封裝本體（F5 `005-repo-intro`，
> 已驗收——F6 **重用**同一 `LlmService`，不另建平行 LLM 客戶端）；Discord 組版與推播、pipeline 端到端
> 編排、榜單日到期判定（`lastBoardPushAt` 計時）、晨報 idempotency guard（`lastNewsPushAt`）、
> `seenNews` 寫回、狀態落檔與 commit（F7 `007-pipeline-push`）。F6 產出的是「可被 F7 取用的精選集
> ＋封面摘要」，本身不組版、不推播、不落檔。

## Clarifications

### Session 2026-07-18

- Q: LLM 同時多選（>6）＋配額違規（非 AI >2）時，程式護欄的套用順序與「遞補 AI」語意為何？ → A: 程式只在「LLM 已選且已繁中改寫」的項目集合內剔除／重排，永不引入 LLM 未改寫的候選；固定順序 (1) 剔除幻覺項＋參照去重 → (2) 依領域優先序夾非 AI ≤2 → (3) 依重要性序截總數 ≤6；夾配額後若不足 6 則照實輸出較少則數（寧缺勿濫）。「遞補 AI」僅指在 6-截斷時優先保留 AI，非引入新候選。
- Q: 降級路徑（無 LLM）是否也須滿足 SC-006 的殘留語意去重（≤1）？ → A: 否。SC-006 僅約束 LLM 成功策展路徑；降級路徑只倚賴 F4 階段 A 的結構性去重，殘留語意重複可能並存於降級前 6，屬已知且接受的有界降級（要求降級做語意去重等於要求呼叫 LLM／建 embeddings，牴觸憲章 V 且與「LLM 不可用」的降級前提矛盾）。

## User Scenarios & Testing *(mandatory)*

本功能的「使用者」即專案擁有者（自用）。擁有者每天想在 Discord 讀到「對開發者最重要的幾則技術
新聞」——不是最熱門的，而是最可能改變自己做事方式的（新工具／版本、breaking change、安全通報、
重大模型／API 發布、deprecation）。上游 F4 已把散落十幾個來源、彼此大量重複的原始新聞，用零 LLM
的結構性手段收斂成一份約 15～25 則、大致無重複的候選集。本 Feature 建立**新聞資料流的最後一段**：
把這份候選集**一次**交給 Gemini，在同一次呼叫內完成殘留語意去重、依開發者重要性挑選、配額約束與
繁中 50/300 改寫，產出每日晨報的精選集；同時把榜單日的變化 diff 摘成一句封面文案。

兩條硬約束貫穿全程：**額度安全**——新聞策展每日**只呼叫 LLM 一次**（用量與候選數無關）、禁用
embeddings／向量檢索；**永不無聲失敗**——策展呼叫失敗時退回純程式排序的降級晨報、榜單摘要失敗時
退回程式產生的事實摘要，任一 LLM 失敗都不得中止晨報或榜單推播。同時，LLM **只做選擇、去重與改寫**，
連結與分數等事實數據一律由程式提供、不經 LLM，並在輸出前以程式硬驗證字數與配額。

本 Feature **不決定「今天是否推新聞／是否榜單日」**（那是 F7 的 guard 與到期判定），也**不組 Discord
版面、不推播、不落檔**。它產出的是「給定候選集 → 回傳合規精選集（或降級精選集）」與「給定榜單 diff
→ 回傳封面摘要（或降級摘要）」兩個可被 F7 取用的能力。

### User Story 1 - 每日單次策展：候選集 → 合規的繁中精選（Priority: P1）

擁有者要每天讀到 ≤6 則、依開發者重要性排序的繁中精選新聞。系統把 F4 的候選集**一次**交給 Gemini，
在同一次呼叫內完成三件事：認出並丟掉階段 A（純結構／字串）漏掉的「其實是同一件事」（殘留語意去重）、
依「重要 ≠ 熱門」挑出最多 6 則、把每則精煉為繁中**標題 ≤50 字＋內容 ≤300 字**。選擇尊重配額
（AI ≥4、DevOps／後端／前端合計 ≤2），且候選不足時照實輸出、不硬湊。連結與分數由程式提供，
LLM 不得杜撰。

**Why this priority**: 這是 F6 的核心產出，也是 M4 里程碑（與 F7 合成）的驗收主體——「候選餵入後
產出合規的 6 則繁中精選」。沒有它，新聞資料流在 F4 的候選集就斷了、無法成為可讀的晨報。它本身即
構成可展示的最小可用產品：給一份候選集，就能得到一份可貼上 Discord 的繁中精選集。

**Independent Test**: 以一份代表性候選集（含跨領域、含一組僅語意重複而階段 A 未除的項、含足量 AI 與
少量非 AI）呼叫策展服務，並以 mock `LlmService` 回傳一段合規的選擇結果，檢視回傳是否為 ≤6 則、
每則繁中且標題 ≤50／內容 ≤300、配額被遵守、每則的連結／分數對得回輸入候選（無杜撰）、且**只呼叫
LLM 一次**。全程 mock LLM，不依賴真實網路或額度。

**Acceptance Scenarios**:

1. **Given** 一份約 15～25 則、已去重排序的候選集，**When** 請求每日策展，**Then** 系統以**單一**
   LLM 呼叫回傳一份 ≤6 則的精選集，每則為繁中標題（≤50 字）＋內容（≤300 字），依開發者重要性排序。
2. **Given** 候選集含一組「不同連結但其實是同一件事」的殘留語意重複，**When** 策展，**Then** 該事件
   在最終精選中**至多出現一次**（殘留語意去重由這唯一一次呼叫順手完成，不另建 embeddings／向量檢索）。
3. **Given** 策展選出的每一則，**When** 檢查其連結與分數，**Then** 這些事實數據**皆取自程式提供的
   來源候選**（以候選參照對回），**不含** LLM 杜撰、輸入候選中不存在的連結或數字。
4. **Given** 候選充足，**When** 策展，**Then** 選擇遵守配額：**AI ≥4**（AI 候選足夠時）、
   **DevOps／後端/前端合計 ≤2**、總數 **≤6**；排序依對開發者的重要性（分數僅為提示、非排序主鍵）。
5. **Given** 某日候選稀少（例如僅 3 則夠格、或某類別掛零），**When** 策展，**Then** 系統照實輸出實際
   數量、**不硬湊滿 6 則**，也不為湊數塞入不重要的熱門文（寧缺勿濫）。

### User Story 2 - 策展失敗的降級備援：晨報永不因 LLM 中斷（Priority: P1）

策展的那一次 Gemini 呼叫可能失敗（429 重試耗盡、空／無效回應、其他錯誤）。此時系統**不擲錯、不中止
晨報**，改退回「純程式排序」的降級路徑：沿用 F4 漏斗已算好的 `weightedScore`（分數＋交叉驗證/tier
＋榜單相關性）取前 6，並尊重同一套配額，每則僅呈現**原文標題＋連結**（無繁中 50/300 改寫）。這是
一個可接受的降級——擁有者仍讀得到當日最重要的幾則，只是少了繁中精煉。

**Why this priority**: 這是憲章原則 VII（來源隔離容錯：任一環節失敗不得使整條 pipeline 失敗、不得
無聲）與原則 VIII（「策展失敗時退回純程式排序」須另測降級備援路徑）在新聞策展環節的直接落實，也是
M4 驗收明列項——「mock 策展失敗仍能輸出降級版晨報（原文標題＋連結）」。優先序 P1：它與 US1 是同一
能力的成功／失敗兩條路徑，且是必測的降級保證，缺了它一次 429 就可能讓整份晨報消失。與 US1 可獨立
驗證：US1 是 LLM 成功路徑，US2 是 LLM 失敗路徑。

**Independent Test**: 以 mock `LlmService` 讓策展呼叫擲錯（模擬 429 耗盡／空回應），呼叫策展服務，
確認回傳一份標記為**降級**的精選集：成員為候選集依 `weightedScore` 的前 6（尊重配額）、每則為原文
標題＋連結（無繁中改寫）、且**未擲錯**（呼叫端得以續跑）；並確認該失敗被記錄（不無聲）。全程 mock。

**Acceptance Scenarios**:

1. **Given** 策展的 LLM 呼叫失敗（重試耗盡／空／無效回應），**When** 請求每日策展，**Then** 系統
   **不擲錯**，改回傳一份**降級**精選集（程式排序前 6、尊重配額、原文標題＋連結），使晨報照常成形。
2. **Given** 進入降級路徑，**When** 產生降級精選，**Then** 排序沿用 F4 漏斗的 `weightedScore`
   （**不重寫一份替代排序公式**），取前 6 且遵守配額（AI ≥4 於候選足夠時、其他合計 ≤2）。
3. **Given** 策展呼叫失敗，**When** 系統降級，**Then** 該失敗 **MUST 被記錄**（`logger.warn`，含可
   追查的脈絡如失敗原因與候選規模，**不含** prompt／LLM 回應全文），**MUST NOT** 無聲略過。
4. **Given** 降級精選集，**When** 呼叫端（F7）取用，**Then** 每則帶明確的**降級標記**，使 F7 能區分
   「繁中精煉版」與「降級版（原文標題＋連結）」而分別渲染。

### User Story 3 - 配額與字數以程式硬驗證：不信任 LLM 自律（Priority: P2）

LLM 可能不完全聽話：回傳超過 6 則、違反配額、標題超過 50 字或內容超過 300 字、甚至夾帶輸入候選中
不存在的項目。系統**不把這些約束只寄望於 prompt**——在輸出前以程式硬驗證：總數 ≤6、配額（AI ≥4／
其他合計 ≤2）、每則標題 ≤50 字＋內容 ≤300 字、每則可對回一個真實輸入候選；違反者由程式收斂
（超量截去、超長收斂）或剔除（無法對應的幻覺項），確保外流的精選集**恆合規**。

**Why this priority**: 這是憲章原則 III（字數上限）、VI（防幻覺、LLM 不產生事實數據）與 VIII（配額與
字數上限須有單元測試）的程式面護欄。優先序 P2：多數情況下 prompt 已讓 LLM 大致守規，但缺了這層
硬驗證，一次不聽話的回應就會讓超長或杜撰內容外流。與 US1 可獨立驗證：US1 驗證正常回應的正確處理，
US3 專門餵入**故意違規**的 mock LLM 回應，驗證程式的收斂與剔除。

**Independent Test**: 以 mock `LlmService` 回傳故意違規的結果（7 則、標題 60 字、內容 400 字、含一個
輸入候選中不存在的杜撰項、AI 只有 3 則但塞了 3 則非 AI），呼叫策展服務，檢視輸出：總數被收斂至 ≤6、
超長標題／內容被收斂至 ≤50／≤300、杜撰項被剔除、配額被夾到 DevOps/後端/前端合計 ≤2。全程 mock。

**Acceptance Scenarios**:

1. **Given** LLM 回傳超過 6 則，**When** 系統驗證，**Then** 依重要性序保留前 6、其餘截去，輸出總數 ≤6。
2. **Given** LLM 回傳的某則標題超過 50 字或內容超過 300 字，**When** 系統驗證，**Then** 該則被收斂至
   ≤50／≤300 字才輸出（不讓超長內容外流）。「字」以 Unicode 字元（code point）計數。
3. **Given** LLM 回傳一則無法對應到任何輸入候選的項目（杜撰／幻覺），**When** 系統驗證，**Then** 該
   項被**剔除**、不進入輸出（連結與事實只能來自程式提供的候選）。
4. **Given** LLM 回傳的選擇違反配額（非 AI 超過 2 則），**When** 系統驗證，**Then** 系統依領域優先序
   夾住非 AI 數量（DevOps/後端/前端合計 ≤2）；夾制後若總數不足 6，**照實輸出較少則數（寧缺勿濫）、
   不從 LLM 未改寫的候選遞補**（避免混入非繁中原文項，牴觸 SC-002）。「遞補 AI」僅指在超過 6 則需
   截斷時優先保留 AI，非引入新候選。

### User Story 4 - 榜單日「本次變化」TL;DR：一句話封面摘要（Priority: P3）

榜單每七天推一次；推的那天，封面 embed 需要一句繁中 TL;DR 概述「本次變化」（例如「本週 3 個新進、
2 個竄升，AI 佔多數」）。系統把榜單 diff（新進／竄升／下降的計數與領域分布）交給 LLM 摘成一句話
（重用 F5 的 `LlmService`，屬 §10 三種 LLM 呼叫中的第 (2) 種、僅榜單日發生）。此摘要**只依程式提供的
diff 事實**、不得杜撰數字；LLM 呼叫失敗時退回**程式產生的事實型摘要**（直接以計數陳述），不阻斷
榜單推播。

**Why this priority**: 它讓榜單封面多一句人味的概述，是 F6 範圍（dev-guide §11.2、§10）明列的第二個
LLM 呼叫。優先序 P3：屬封面裝飾性文案、僅榜單日發生，缺了它榜單卡片仍可推（封面退回事實型摘要即可），
不影響每日新聞主線。與 US1～US3 可獨立驗證：它吃的是榜單 diff、不吃新聞候選集，是一條獨立的小能力。

**Independent Test**: 以一組榜單 diff（含新進／竄升／下降的計數與領域）呼叫摘要服務，mock `LlmService`
回傳一句繁中摘要，檢視回傳為一句不杜撰、依 diff 事實的繁中文案；再讓 `LlmService` 擲錯，確認退回
程式產生的事實型摘要（如「本週 N 個新進、M 個竄升、K 個下降」）、未擲錯、且記錄該失敗。全程 mock。

**Acceptance Scenarios**:

1. **Given** 一組榜單變化 diff（新進／竄升／下降的計數與領域分布），**When** 請求封面摘要，**Then**
   系統以一次 LLM 呼叫回傳一句繁中 TL;DR，內容**僅依 diff 提供的事實**、不杜撰未提供的數字或名稱。
2. **Given** 摘要的 LLM 呼叫失敗，**When** 系統降級，**Then** 退回**程式產生的事實型摘要**（以 diff
   計數直接陳述），**不擲錯、不阻斷榜單推播**，並記錄該失敗（不無聲）。
3. **Given** 榜單無任何變化（新進／竄升／下降皆為空），**When** 請求封面摘要，**Then** 系統回傳一段
   代表「本次無變化」的摘要（此情形是否推榜由 F7 決定，本服務只負責在被呼叫時給出合規摘要）。

### Edge Cases

- **候選集為空**（某日階段 A 產出 0 則）：策展照實回傳**空精選集**，**MUST NOT** 呼叫 LLM 去無中生有
  （零候選即零可選，省下該次呼叫）；此空集合是否推新聞由 F7 決定。
- **候選全為非 AI**（當日完全沒有夠格的 AI 新聞）：配額 AI ≥4 是「候選足夠時」的軟性下限，此時照實
  輸出非 AI 精選（仍受合計 ≤2、總數 ≤6 約束），不因湊不到 4 則 AI 而失敗或硬塞。
- **LLM 回傳格式無法解析**（非預期結構／非 JSON／截斷）：視同策展失敗，走 US2 降級路徑，不擲錯。
- **LLM 回傳的候選參照重複**（同一輸入候選被選兩次）：去重後只計一次，避免同一則在精選中重複出現。
- **殘留語意重複跨越配額類別**（同一事件在 AI 與非 AI 各有一個連結）：語意去重後只留一則，其領域依
  留下的代表項計入配額。
- **繁中改寫夾雜英文詞句**：系統**不做**嚴格語言偵測或語言比例校驗；繁中約束**以 prompt 為主**，程式
  面只硬驗證字數（≤50／≤300，超長收斂）與非空、與可對回候選。夾雜英文詞句為**已知且接受的有界風險**
  （沿用 F5 對簡介的同一取捨），非本 Feature 需消除的缺陷。
- **降級精選的原文標題超過 50 字**：降級路徑呈現的是原文標題＋連結、非繁中改寫，**不套用** 50 字硬
  驗證收斂（原文照實呈現屬降級語意的一部分；字數上限只約束繁中精煉版）。
- **降級路徑遇殘留語意重複**：降級（無 LLM）僅倚賴 F4 階段 A 的結構性去重，無法做語意去重（憲章 V
  禁 embeddings，且降級前提即 LLM 不可用），故降級前 6 可能並存同一事件的不同連結——此為**已知且
  接受的有界降級**，SC-006 不適用於降級路徑（見 Clarifications 2026-07-18）。
- **榜單 diff 僅有下降、無新進／竄升**：封面摘要照實陳述（下降側純位移噪音沿用 F3 已接受的設計），
  不因「只有下降」而略過摘要。

## Requirements *(mandatory)*

### Functional Requirements

**每日單次策展（NewsCurationService · 階段 B）**

- **FR-001**: 系統 MUST 提供「給定一份候選集（F4 `CandidateSet`）＋當前榜單脈絡，回傳當日精選集」的
  能力；呼叫端（F7）不需自行做語意去重、重要性挑選或繁中改寫。**輸入契約**：候選集由 F4 漏斗產出並
  由呼叫端傳入；「候選是否命中當前榜上 repo」的脈絡（供重要性加權提示）由**呼叫端**隨候選傳入，
  NewsCurationService **MUST NOT** 自行抓取榜單或新聞來源。
- **FR-002**: 系統 MUST 以**單一** LLM 呼叫完成新聞策展；整個新聞流程對 LLM 的用量 MUST 固定為
  「每日 1 次」，**與候選數無關**。**MUST NOT** 引入 embeddings／向量檢索，或為策展發起多於一次的
  LLM 呼叫（憲章 V）。
- **FR-003**: 該次策展呼叫 MUST 在**同一次呼叫**內完成三件事：(a) **殘留語意去重**——認出並丟掉階段 A
  未除的「其實是同一件事」；(b) **依開發者重要性挑選** ≤6 則——prompt MUST 明確「重要 ≠ 熱門」，優先
  會改變開發者做事方式的內容（新工具／框架／版本、breaking change、安全通報、重大模型／API 發布、
  標準變動、重大 deprecation），壓低純爆紅口水／drama／純觀點文，且**分數僅為提示、非排序主鍵**；
  (c) **每則精煉為繁中標題 ≤50 字＋內容 ≤300 字**，內容說清「發生什麼事＋為何對開發者重要」。
- **FR-004**: 策展選擇 MUST 遵守配額：**AI ≥4**（AI 候選足夠時的軟性下限）、**DevOps／後端／前端
  合計 ≤2**、總數 **≤6**。非 AI 的取捨依領域優先序（DevOps 優先，後端只看 Node.js／Python，前端以
  TypeScript 為主、Vue／React 最低，CSS 技巧／教學一律不選）——此主題降噪 MUST 於此策展呼叫外顯執行
  （F4 階段 A 刻意不做，見 `specs/004-news-ingest` FR-028）。
- **FR-005**: 候選不足時系統 MUST 照實輸出實際數量、**MUST NOT 硬湊滿 6 則**；某類別掛零亦照實
  （配額是「上限／軟性下限約束」而非「硬性填滿」，寧缺勿濫）。
- **FR-006**: 每則精選的**連結與分數等事實數據 MUST 由程式提供**（以候選參照對回輸入候選後附上），
  **MUST NOT** 由 LLM 產生或竄改；LLM 的輸出 MUST 只用於「選擇（以候選參照）、去重與繁中標題／內容
  改寫」（憲章 VI 防幻覺）。
- **FR-007**: 系統 MUST 只將**公開資料**（候選的 title／domain／tier／score／sources 數／是否命中
  榜上 repo／summary 節錄）送交 LLM，符合免費層資料使用條款；**MUST NOT** 送出任何機密。

**輸出硬驗證（不信任 LLM 自律）**

- **FR-008**: 系統 MUST 在輸出前以程式硬驗證並收斂 LLM 的策展結果：總數超過 6 則 MUST 依重要性序
  截去至 ≤6；標題超過 50 字或內容超過 300 字 MUST 收斂至 ≤50／≤300 才輸出。「字」MUST 以 Unicode
  字元（code point）計數（與 F5 簡介、憲章字數口徑一致）。
- **FR-009**: 系統 MUST 剔除 LLM 回傳中**無法對應到任何輸入候選**的項目（杜撰／幻覺），使每則輸出
  精選皆可對回一個真實候選；重複參照同一候選者 MUST 去重為一則。
- **FR-010**: 系統 MUST 於輸出前夾住配額：非 AI（DevOps／後端／前端）合計超過 2 則時 MUST 依領域
  優先序截去超出部分；總數／各類別 MUST 落在 FR-004 的界限內。此夾制 MUST 為程式面保證，不僅依賴
  prompt。**護欄套用順序固定為**：(1) 剔除幻覺項＋重複參照去重（FR-009）→ (2) 依領域優先序夾非 AI
  ≤2（本條）→ (3) 依重要性序截總數 ≤6（FR-008）。程式 MUST 只在「LLM 已選且已繁中改寫」的項目集合
  內剔除／重排，**MUST NOT** 為湊足 6 則而從 LLM 未改寫的候選遞補新項（將使輸出混入非繁中原文項，
  牴觸 SC-002）；夾制後總數不足 6 時 MUST 照實輸出較少則數（寧缺勿濫）。

**策展失敗的降級備援（憲章 V／VII／VIII）**

- **FR-011**: 策展的 LLM 呼叫失敗（`LlmError` 重試耗盡／空／無效回應，或回應無法解析）時，系統
  **MUST NOT 向呼叫端擲錯、MUST NOT 中止晨報**，改回傳一份**降級精選集**。
- **FR-012**: 降級精選集 MUST 以**純程式排序**產生：沿用 F4 漏斗已算好的 `weightedScore`（分數＋
  交叉驗證/tier＋榜單相關性）取前 6，並遵守同一套配額（FR-004）；**MUST NOT** 重寫一份替代排序公式
  （沿用「引用既有的尺、不另發明」的紀律，比照 F3 引用 F2 `weeklyStarsEstimate()`）。
- **FR-013**: 降級精選的每則 MUST 呈現**原文標題＋連結**（無繁中 50/300 改寫），且 MUST 帶明確的
  **降級標記**，使呼叫端（F7）能區分「繁中精煉版」與「降級版」而分別渲染。降級版原文標題 MUST NOT
  套用 50 字收斂（原文照實呈現，字數上限只約束繁中精煉版）。
- **FR-014**: 策展失敗時該失敗 MUST 被記錄（`logger.warn`，內容 MUST 含可追查脈絡如失敗原因與候選
  規模，**MUST NOT** 含 prompt 或 LLM 回應全文），**MUST NOT** 無聲略過。此 warn 為 F6 對該失敗的
  回報形式——**MUST NOT** 由 F6 發送 Discord 告警或任何推播（面向使用者的紅色告警 embed 屬 F7 推播層
  職責，F6 不組版、不推播）。

**榜單日「本次變化」TL;DR（§10 第 (2) 種 LLM 呼叫）**

- **FR-015**: 系統 MUST 提供「給定榜單變化 diff（新進／竄升／下降的計數與領域分布），回傳一句繁中
  封面 TL;DR」的能力，**重用 F5 的 `LlmService`**（不另建平行 LLM 客戶端）。此摘要 MUST 只依 diff
  提供的事實、**MUST NOT** 杜撰未提供的數字或名稱（憲章 VI）。
- **FR-016**: 封面 TL;DR 的 LLM 呼叫失敗時，系統 **MUST NOT 擲錯、MUST NOT 阻斷榜單推播**，改退回
  **程式產生的事實型摘要**（以 diff 計數直接陳述，如「本週 N 個新進、M 個竄升、K 個下降」），並記錄
  該失敗（`logger.warn`，不無聲）。
- **FR-017**: 榜單日 TL;DR 屬**僅榜單日發生**的呼叫，與每日新聞策展的「每日 1 次」相互獨立、不衝突
  （§10 三種 LLM 呼叫各自獨立）；本 Feature MUST NOT 因新增此呼叫而使新聞策展變成多次呼叫。

**LLM 重用與狀態邊界（憲章 V／VI）**

- **FR-018**: 本 Feature 的所有 LLM 呼叫 MUST 重用 F5 的 `LlmService`（含其 429/503 指數退避＋jitter
  重試、只送呼叫端 prompt 的既有行為），**MUST NOT** 另建平行 LLM 客戶端或重複實作退避邏輯。
- **FR-019**: 本 Feature **MUST NOT** 呼叫 `StateStore.save()` 落檔、**MUST NOT** 做任何 git commit、
  **MUST NOT** 寫回 `seenNews`（把入選項標記為已見）；`seenNews` 寫回與狀態持久化之時機屬 F7
  「推播成功後」（憲章 VI「狀態必須在推播成功後才寫回」）。F6 產出的精選集／封面摘要僅為記憶體結構，
  交由 F7 組版、推播、於成功後統一落檔。
- **FR-020**: 候選集為空時系統 **MUST NOT** 呼叫 LLM 策展（零候選即零可選），直接回傳空精選集；
  是否因空集合略過新聞段由 F7 判定。

### Key Entities *(include if feature involves data)*

- **策展輸入項（Curation item view）**：送交 LLM 的每一則候選的公開脈絡投影——`title`、`domain`、
  `tier`、`score`、`sources` 數（交叉驗證強度）、是否命中當前榜上 repo、`summary` 節錄，外加一個
  **穩定參照鍵**（供 LLM 回傳選擇時對回原候選、附上程式提供的連結／分數）。只含公開資料。
- **精選新聞（CuratedNewsItem）**：策展輸出的一則。繁中改寫版含 `title`（≤50 字）、`content`
  （≤300 字）、`domain`、以及**程式提供的**連結與來源事實；並帶來源候選參照與一個**降級標記**
  （成功策展為精煉版；策展失敗的降級版帶原文標題＋連結、標記為 `degraded`）。
- **晨報精選集（Morning digest selection）**：當日 ≤6 則精選的有序集合，遵守配額（AI ≥4 於候選足夠
  時、DevOps/後端/前端合計 ≤2、總數 ≤6），依開發者重要性排序。存在於單次執行期間，交 F7 組版推播。
- **榜單變化摘要（BoardChangeSummary）**：榜單日封面的一句繁中 TL;DR，含摘要文字與一個**降級標記**
  （LLM 成功為改寫版；失敗為程式產生的事實型摘要）。輸入為榜單 diff 的計數與領域分布（由 F7 傳入）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 新聞策展對 LLM 的呼叫次數**恆為 1**——對任意候選規模（15、25 或更多）重複執行，策展的
  LLM 呼叫次數皆為 1；候選集為空時為 0（不無中生有）。用量與候選數無關（憲章 V）。
- **SC-002**: 輸出精選（繁中精煉版）**100%** 為繁中且標題 **≤50 字**、內容 **≤300 字**——即使 LLM
  回傳超長，經收斂後仍符合（字以 code point 計）。
- **SC-003**: 策展選擇 **100%** 遵守配額：AI ≥4（AI 候選足夠時）、DevOps/後端/前端合計 ≤2、總數 ≤6；
  候選不足時輸出實際數量、硬湊比率為 **0**（SC 以「未超出上限、且未為湊數塞入」雙向驗證）。
- **SC-004**: 策展呼叫失敗時 **100%** 能產出降級晨報（程式排序前 6、尊重配額、原文標題＋連結），
  且晨報不中止——單筆策展失敗造成的連帶中止數為 **0**（M4 驗收核心：「mock 策展失敗仍能輸出降級版」）。
- **SC-005**: 每則輸出精選的連結／分數 **100%** 可對回一個真實輸入候選；LLM 回傳中無法對應輸入候選
  的杜撰項出現在輸出的次數為 **0**（防幻覺，憲章 VI）。
- **SC-006**: 對一組**刻意含殘留語意重複**（同一事件、不同連結，階段 A 未除）的候選輸入，**在 LLM
  成功策展路徑**下最終 6 則精選中該事件出現次數 **≤1**（殘留語意去重由單次策展呼叫達成，無需
  embeddings）。**此 SC 不約束降級路徑**——降級（無 LLM）只倚賴 F4 階段 A 的結構性去重，殘留語意
  重複可能並存，屬已知且接受的有界降級。
- **SC-007**: 榜單日 TL;DR 的 LLM 呼叫失敗時 **100%** 能以程式產生的事實型摘要備援輸出，榜單推播不
  因此中止；備援摘要的數字 **100%** 取自程式提供的 diff（0 起杜撰）。

## Assumptions

- **候選集由 F4 提供、榜單脈絡由呼叫端傳入**：F6 消費 F4 漏斗產出的 `CandidateSet`（已去重、過濾、
  排序、帶 `weightedScore`）；「候選是否命中當前榜上 repo」等榜單脈絡由呼叫端（F7）以當次榜單資料
  補上後隨候選傳入。F6 不重新抓取新聞或榜單。
- **LLM 為 Gemini 免費層 Flash 系、重用 F5 `LlmService`**：憲章原則 I 釘死；F6 不另建 LLM 客戶端，
  直接注入 F5 的 `LlmService`（`src/llm/llm.service.ts`，含 429/503 指數退避＋jitter）。策展與封面
  TL;DR 皆透過同一入口。
- **LLM 的結構化回傳格式於 `/speckit-plan` 釘定**：策展需讓 LLM 回傳「選了哪些候選（以參照鍵）＋每則
  繁中標題／內容」，其確切格式（如 JSON schema、參照鍵形式）屬實作細節，於 `/speckit-plan` 確認；
  本規格層面只要求「可對回輸入候選、可硬驗證字數與配額」。
- **「字」以 Unicode 字元（code point）計數**：與 F5 簡介、憲章 50/300/250 字數口徑一致。
- **超長輸出以收斂處理**：標題／內容超過上限時採「收斂至 ≤50／≤300（必要時於自然邊界並加省略標記）」，
  **不**因超長而重呼叫 LLM 重生成（避免額外額度消耗，沿用「一切從簡」取捨）。
- **降級排序沿用 F4 `weightedScore`**：降級路徑不重寫排序公式，直接取候選集依 `weightedScore` 的前 6
  並套配額（比照 F3 引用 F2 既有的尺、不另發明）。
- **主題降噪（後端只看 Node.js/Python、前端以 TypeScript 為主、不收 CSS）於策展 prompt 外顯執行**：
  F4 階段 A 刻意不以關鍵字硬篩內容主題（`specs/004-news-ingest` FR-028），此語意判斷留在本 Feature
  的單次 LLM 策展執行。
- **不落檔、不推播、不寫 `seenNews`**：F6 只產出記憶體結構；狀態持久化、`seenNews` 寫回、Discord
  組版與推播、晨報 idempotency guard 與榜單到期判定一律屬 F7（推播成功後才寫回，憲章 VI）。
- **繁中約束以 prompt 為主、程式只硬驗證字數與配額**：不做嚴格語言偵測；夾雜英文詞句為已知且接受的
  有界風險（沿用 F5 對簡介的同一取捨）。
- **退避參數沿用 F5**：429/503 指數退避＋jitter 的重試上限與退避基準／上限值沿用 `LlmService` 既有
  設定（`llm.types.ts`），本 Feature 不另調。
