# 0006. 策展回應：結構化輸出、解析失敗改用備援重試、仍失敗逐則搶救

- **相關**：憲章 V（每日一次策展）、VII（log 不含回應全文、失敗須告警）；開發指南 §2.4、§4.4 階段 B、§8.x；

## 脈絡

2026-10-08（台北）gemini-3.8-flash 首次呼叫就成功、finishReason=STOP，但只輸出 651 tokens／1,391 字元（正常日 2.7k～4.5k 字元）。
`officialPicks` 中至少一則形狀不符，`parsePickArray` 擲錯 → 整份走 `fallbackDigest`：15 則英文原文標題、無摘要（含 GPT‑6、
Claude Haiku 5.5），且照常寫入 `seenNews`，之後不會再被策展。三個設計疊加放大了單一則的失誤：

1. 呼叫未用 Gemini 結構化輸出，形狀只靠 prompt 約束。
2. `generateWithModelFallback` 只攔 `LlmError`，解析失敗不換備援型號（2026-09-12 原設計：「那是回應內容問題，不是型號問題」）。
3. 解析全有全無（F6 research D2「不做局部搶救」）。

另外 log 依憲章 VII 不記回應全文，也沒記壞項的形狀，事後無從確證是缺欄位還是型別錯。

## 決策

1. **結構化輸出**：策展主、備援呼叫皆帶 `responseMimeType: application/json`＋`responseJsonSchema`（`CURATION_RESPONSE_JSON_SCHEMA`，
   與 prompt 輸出規則同步）。型號以 400 拒絕進階設定時，沿用既有防禦：warn 後以不帶 thinking／schema 的純請求重送一次。
2. **診斷 log**：解析失敗時印壞項的陣列鍵、索引、各鍵 `typeof`（缺席標「缺」），非 JSON 時印回應字元數；不含任何標題或內容。
3. **解析失敗改用備援重試一次**：主型號回應有結構性錯誤或任一則形狀不符 → 以備援型號（Lite）同 prompt 重試一次。主型號已因
   `LlmError` 改用備援者不再呼叫第三次。仍是同一份策展的重試，最多主型號一輪＋備援一輪，憲章 V 不變。
4. **仍失敗則逐則搶救**：取備援完整回應；否則在可解析的兩份回應中取可用則數多者（平手取主型號），丟掉形狀不符的項目、保留其餘；
   兩份皆無可用項目才退回原文標題版並發紅色告警。
5. **降級日補發**：新增 `NEWS_REPLAY_DATE`（workflow_dispatch `replay_date`，隱含乾跑）——以該台北日 `seenNews` 已推的原始標題重建
   候選、**逐則翻譯、不重新篩選**（`translateForReplay`，未回者保留原文標題），先送一則 warning embed 再送翻譯版，全部推到告警頻道，不寫狀態。

## 否決的替代方案

- **只做結構化輸出＋診斷 log，Lite 重試與逐則搶救列為選項**（Agent 提案）→ 使用者裁決兩者都做，且順序為「先改用 Lite 重試、仍失敗才丟壞項」。
  理由（使用者，2026-10-17）：Lite 免費額度較寬裕，失敗日多一次重試的代價低，值得先換型號拿一份完整回應，再退到丟壞項。
- **解析失敗不換型號**（2026-09-12 原設計）→ 推翻。10-08 實證一則形狀錯就讓整份晨報降級，而備援是獨立型號、獨立配額，重試代價只有失敗日多一次 Lite 呼叫。
- **解析全有全無、不做局部搶救**（F6 research D2）→ 推翻。可用的繁中改寫項目整份丟掉、改推原文標題，損失大於少推幾則；
  與 2026-09-12 起「未知頂層鍵只 warn 不降級」的方向一致。
- **降級日不寫 `seenNews`，讓隔日重新策展推到晨報頻道** → 未採。會讓隔日晨報混入前一天的新聞，且降級的原文標題版已經推出；
  改以手動補發到告警頻道，由使用者決定何時補。
- **補發沿用每日策展（重新篩選）**（首版實作）→ 同日改為只翻譯。10-08 補發實測 15 則只選 5 則，GPT‑6、Claude Haiku 5.5 皆未入選：
  候選只有標題、無摘要無分數，策展判準在素材不足時偏嚴；而補發的項目當天早已推出，目的是補繁中版而非重選。Agent 建議、使用者同意。

## 後果與觀察

- 結構化輸出是否被 `gemini-3.8-flash`／`gemini-3.5-flash-lite` 在 thinking=high 下接受，本機無 `GEMINI_API_KEY` 無法驗證；
  以補發模式的實際執行驗證（用量 log 帶 `schema=json`、無「拒絕 thinking／結構化輸出設定」warn）。若被拒，每天會多一次 400 重送且失去 thinking，須另案處理。
- 看什麼：Actions log「策展回應解析不完整」「策展回應丟棄形狀不符 N 則」與完成 log 的型號字樣；告警頻道的「晨報策展降級」應只在主備皆無可用項目時出現。
- 補發的候選只有原始標題、沒有原文摘要，內容只能依標題撰寫、篇幅較短；prompt 要求「寧短勿編」。
- 已驗證（補發 run 39037275115）：`gemini-3.8-flash` 在 thinking=high 下接受 `responseJsonSchema`，log 帶 `schema=json`、無拒絕 warn。
