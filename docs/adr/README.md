# 架構決策紀錄（ADR）

每份 ADR 記一個**仍在影響設計的決策**：它的脈絡、被否決的替代方案與理由、裁決、後果。
這裡回答「為什麼當初這樣決定」；**現況**寫在 [開發指南](../tech-radar-dev-guide.md)，
**非協商原則**寫在 [憲章](../../.specify/memory/constitution.md)，**觀察數據**寫在 `docs/plans/`。
三者分工見 [CLAUDE.md](../../CLAUDE.md)「真實來源」一節。

## 寫法

- 檔名 `NNNN-短名.md`，編號遞增、不重用。每份控制在半頁，超過就是兩個決策。
- **推翻紀錄**（Agent 提案被使用者否決、或使用者原做法被 Agent 說服而改變）寫進「否決的替代方案」欄：
  原提案、裁決、理由，三者都要有；理由不明就問，不自行推測。
- 決策被翻案時**不改寫舊 ADR**：新開一份、在新舊兩邊的「狀態」互相連結（`Superseded by 000N` / `Supersedes 000M`）。
- 只為「有替代方案、且日後會被問為什麼」的決策開 ADR；純修 bug、純重構不開。
- 2026-10-06 以前的決策留在開發指南的內嵌段落，不回填；本目錄從第六批調整起算。

## 模板

```markdown
# NNNN. 標題（一句話說出決策本身）

- **狀態**：Accepted | Superseded by NNNN | Deprecated
- **日期**：YYYY-MM-DD（首次裁決）；YYYY-MM-DD 重申／修訂
- **相關**：憲章原則、開發指南章節、主要程式路徑

## 脈絡
（為什麼此時要決定；附證據數字）

## 決策
（做了什麼；一到三句）

## 否決的替代方案
（每個方案一行：方案 → 否決理由。推翻紀錄寫在這裡，標明提案方與裁決方）

## 後果與觀察
（代價、風險、退場條件、要看哪個 log／指標）
```
