# 0005. 跨日標題去重：seenNews 記標題、近 14 天 Jaccard

- **狀態**：Accepted（限度已知，候補方案待決）
- **日期**：2026-10-06
- **相關**：憲章 V（去重零 LLM）；開發指南 §4.4 第 6 步；`src/news/seen-news.ts` `excludeSeenByTitle`、`src/curation/curation.types.ts` `sourceTitle`、`src/state/state.schema.ts`

## 脈絡

`seenNews` 只比對正規化 URL。1.3.1 上線九天（09-28～10-06）內同一事件換連結再出現而重推：荷蘭 NixOS（dawo.community → 制裁報導）、Gemini 4 Argon（deepmind blog → HN 投稿）、Sonnet 5.5（Copilot changelog → HN），Kolibri 三天不同角度。標題相似度去重原本只在當日候選池內運作。

## 決策

1. `CuratedNewsItem` 新增 `sourceTitle`（候選原始標題，程式提供、非 LLM 改寫的繁中標題）；推播成功寫回 `seenNews` 時連同 `title` 落檔。兩欄皆選用，舊 state 載入不受影響。
2. 漏斗在 URL 排除已見之後，對近 **14 天**帶標題的已推紀錄做 `normalizeTitle`＋Jaccard ≥ **0.6** 比對，命中即排除並在 log 列出「候選≈已推」配對。14 天與當日池內標題合併的視窗同一把尺；不用整個 45 天保留期，以免一個月前的舊事件壓掉同名新版本。

## 否決的替代方案

- **用 LLM 改寫的繁中標題比對** → 同一事件兩天的繁中改寫措辭不同，且與英文候選標題無法比對。
- **回看整個 45 天保留期** → 同名新版本（如 Gemini 4 → 4.1）會被一個月前的舊事件壓掉。
- **門檻降到 0.4** → 可接住 Argon（0.43）、Sonnet 5.5（0.40）兩組，但「Sonnet 5.5 深度評測」這類合理後續文也可能被誤殺，風險未評估。列為候補、未採。

## 後果與觀察

- **已知限度（實作時量測）**：三組重推實例的原始標題 Jaccard 為 0.23（NixOS）／0.43（Argon）／0.40（Sonnet 5.5），皆低於 0.6。本機制只接得住「同一篇換連結」或措辭高度重疊的標題；上述實例是「同主題、不同報導」，是否重推屬語意判斷，零 LLM 層不應誤殺同主題的新進展。
- **候補方案（待使用者決策）**：把近 7～14 天已推標題投影進策展 prompt，讓 LLM 判斷「已報導過，除非有新事實」。仍是同一次呼叫（憲章 V 不變），約 +2～4k tokens。
- 代價：`seenNews` 每筆多一個標題，體積約增三成；合併隔日才開始有帶標題的紀錄可比對。
- 看什麼：log「排除近 14 天已推相似標題後：N 則（-k）：配對…」的每日命中數與配對是否合理。
- **回看時點與判讀標準（2026-10-06 與使用者約定，約 2026-10-13 回看）**：Jaccard 層接不住的案例不會留 log，須另從每日
  「策展入選 N 則」清單跨日比對、數同一事件不同報導的組數。每週 ≤1 組 → 現狀夠用、候補不做；每週 ≥2～3 組且多為「同主題
  不同報導」而非換連結 → 做 prompt 投影；Jaccard 配對出現明顯不同文章（誤殺）→ 先調高門檻，再談候補。
