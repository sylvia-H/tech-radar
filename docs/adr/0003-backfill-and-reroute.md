# 0003. 補位陣列：資安與一般軟體工程補位、誤放者回流主桶

- **狀態**：Accepted
- **日期**：2026-09-26 裁決（憲章 1.8.0）；2026-09-27 修訂（回流取代剔除）
- **相關**：憲章 III 補位條款；開發指南 §4.4；`src/curation/curation-validate.ts`、`src/curation/curation-prompt.ts`

## 脈絡

ADR 0002 上線首日（2026-09-26）晨報只有 7 則且全 AI。未歸類 10 則中的 F-Droid 2.0、Snapdragon 支援 Linux、FBI 被駭對開發者有價值，但不屬 AI／DevOps／前後端三桶，LLM 正確地全數不選。使用者定位：資安與一般軟體工程本質上就是「未歸類高熱度」，只在則數未滿且沒有更優先的 AI 新事物時補位，不是擴大晨報範圍。

補位上線首日（2026-09-27）LLM 把 Node.js v24.21.0 LTS 發布（前後端、合格的官方發布）放進補位陣列，`backfill-scope` 規則把它整則丟掉，當日 7 選 → 6 推。

## 決策

1. 策展回應第三陣列 `backfillPicks`，只收未歸類候選中的資安事件與一般軟體工程新聞。三桶精選完成配額與總數截斷**之後**才處理：只補到 15、永遠排最後、不計入非 AI 配額，領域記為 `general`。
2. 已歸類候選被放進補位陣列時**回流主桶**：視同 `communityPicks` 尾端併入，照常套去重、來源多樣性、非 AI 配額與總數截斷，領域沿用程式歸類，並以 warn 揭露。放錯陣列是分類錯誤，不該變成入選錯誤。

## 否決的替代方案

- **擴大三桶定義納入資安與一般軟體工程** → 違反「AI 為主」的領域配置；補位讓它們只在有餘裕時出現。
- **第四桶配額** → 需修憲章 III／V，且首日證據只有一天；先以補位觀察。
- **誤放補位的已歸類候選直接剔除（2026-09-26 原設計）→ 2026-09-27 改回流**：剔除的是 LLM 已選、已改寫繁中的合格候選，淨損失一則官方發布。回流仍只在 LLM 已選集合內重排、不遞補新候選（FR-005/010）。

## 後果與觀察

- 09-28～10-06 補位共 6 則，內容全屬資安或一般軟體工程、無誤選；回流 warn 0 次（LLM 分類錯誤未再發生）。補位少是因為三桶多數日子已選滿 15，符合設計。
- 看什麼：log「補位 N 則」、「補位陣列含已歸類候選，已回流主桶套配額」（天天出現即收緊 prompt 補位段）。
