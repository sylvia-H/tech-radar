# 0007. 跨日同題：近五天已推標題投影進策展 prompt

- **狀態**：Accepted（觀察中）；實作 [ADR 0005](0005-cross-day-title-dedup.md) 的候補方案
- **日期**：2026-10-17
- **相關**：憲章 V（每日一次策展、去重主力零 LLM）；開發指南 §4.4 階段 B；`src/curation/recent-pushed.ts`、`curation-prompt.ts`、
  `src/pipeline/news-segment.service.ts`

## 脈絡

ADR 0005 的 URL＋Jaccard 跨日去重只接得住「同一篇換連結」。2026-10-17 依其判讀標準回看：10-07～10-17 入選清單跨日比對，同一事件的
不同報導每週 ≥3 組（Deno×Cloudflare、Python 3.15、k8s cgroup、Gemini 4 Argo、LFM2.5、Void、AdFection、OpenCode 2.0、Beam 501B），
達到「做 prompt 投影」門檻。重推間隔多為 1～4 天。

## 決策

1. 晨報策展（正式與乾跑）把 `seenNews` 中近 **5 天**帶原始標題的已推紀錄投影進 prompt：新到舊、同標題去重、每則截 **60** 字、最多 **100** 則，
   列在「候選標記說明」之後、「輸出規則」之前，明示「只供比對、不是候選、不得回傳」。
2. 規則：候選與已推報導是同一件事、且沒有新事實 → 不選；換連結、換來源、換角度或評論都算重複。有實質新進展者照常評估（預告或測試版後的
   正式發布、新版本、事故事後報告、撤回或更正、已生效判決）；無法確定時照常評估。段落文字不寫天數（錨定防線）。
3. 仍是同一次呼叫，不增加請求數；ADR 0005 的零 LLM 層保留，兩層並存。

## 否決的替代方案

- **投影 7 天**（Agent 提案）→ 使用者改為 5 天。理由（使用者）：重推多半間隔 1～4 天，5 天已涵蓋，且 prompt 較小。
- **Jaccard 門檻降到 0.4**（ADR 0005 候補之一）→ 不採。重推實例多是不同措辭的不同報導（Jaccard 0.23～0.43），降門檻接不住多少，誤殺同主題新進展的風險卻上升。
- **投影 14 天（與 Jaccard 層同視窗）** → 不採。約 200 則、+3～4k tokens，使用者擔心 prompt 增大影響 Flash 失敗率。

## 後果與觀察

- 成本：以 2026-10-17 的 state 實測約 72 則、4.2k 字元，估計 +1.2～1.4k tokens（約 +18%）；輸出長度不變。現有證據顯示 Flash 失敗為 503 容量問題、
  與 prompt 大小無相關（10-16 最大 prompt 17.8k 字元成功、10-07／10-09 較小者失敗），但無法事前證明。
- **退場條件**：上線後一週，Flash 改用 Lite 的天數明顯高於基準（10-10～10-17 為 0 次）或出現 MAX_TOKENS → 把 `RECENT_PUSHED_WINDOW_DAYS` 設為 0 關閉投影
  （只改常數）。另看入選清單是否誤殺同主題的新進展。
- 看什麼：log「策展輸入：…近期已推 N 則供比對」、用量 log 的輸入／思考 token；入選清單跨日比對的同題組數，目標每週 ≤1 組。
